# Оптимизатор локализации — воркфлоу

Три независимые фазы. Фазы 2 и 3 читают кэш Фазы 1, но запускаются отдельно.

---

## Обзор

```
Фаза 1 — Анализ       →  картина состояния + сценарии экономии
Фаза 2 — Roadmap      →  13-недельный прогноз + план перемещений
Фаза 3 — Перестановки →  операционный план: что, откуда, куда, сколько
```

Фаза 1 запускается редко (когда нужна свежая картина). Фаза 3 — регулярно, по мере изменения остатков.

---

## Фаза 1 — Анализ ИЛ/ИРП

### Что делает

- Запрашивает заказы за указанный период из WB API
- Считает ДЛ, КТР, КРП по каждому артикулу и каждому ФО
- Строит сценарии: что будет с расходами при достижении 30/40/50/60/70/80/90% ДЛ
- Записывает результат в Google Sheets (4 листа) и в кэш

### Команда

```bash
python localization/run_analysis.py ooo --days 90
```

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `cabinet` | Имя кабинета из `cabinets.yaml` (позиционный) | обязательный |
| `--days` | Глубина истории заказов | 30 |

### Google Sheets — что появится

**Лист «ИЛ Анализ»**

Сводка по кабинету: текущий ИЛ, ИРП, сколько артикулов в ИРП-зоне, суммарная переплата.

**Лист «Экономика сценариев»**

Таблица: если бы ДЛ была 30%, 40%, … 90% — сколько бы стоила логистика. Показывает потенциал экономии.

**Лист «Регионы»**

По каждому ФО: доля заказов, текущая локализация, сколько остатков лежит «правильно».

**Лист «Проблемные SKU»**

Топ артикулов по вкладу в высокий КТР — с чего начинать перемещения.

### Кэш

После запуска результат сохраняется в:
```
localization/data/cache/{cabinet}_latest.json
```

Фазы 2 и 3 читают этот файл. Если кэш старше 24 часов — они предупредят и предложат пересчитать.

---

## Фаза 2 — 13-недельный Roadmap

### Что делает

- Читает кэш Фазы 1
- Определяет какие артикулы и куда переложить для достижения целевого ДЛ
- Симулирует динамику ИЛ по неделям с учётом инерции 13-недельного окна
- Показывает вехи: когда исчезнет ИРП (60%), когда достигнем КТР 0.80 (80%)

### Команда

```bash
python localization/run_roadmap.py ooo
```

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `cabinet` | Имя кабинета (позиционный) | обязательный |
| `--target` | Целевой ДЛ % | 85 |
| `--limit` | Макс. доля остатков для перемещения | 0.3 |

### Google Sheets — что появится

**Лист «Перестановки Roadmap»**

- По неделям: прогнозный ДЛ, КТР, ИРП
- Отмечены ключевые вехи (пересечение 60% и 80%)
- По артикулам: сколько единиц куда переложить

### Как читать результат

Roadmap показывает **план**, не **операцию**. Он отвечает на вопрос «что нужно сделать всего» — без разбивки по дням и без учёта текущих остатков.

Для операционного плана с учётом остатков и лимитов складов — Фаза 3.

---

## Фаза 3 — Операционные перестановки

### Что делает

- Запрашивает **текущие остатки** по складам из WB API (live данные)
- Читает ДЛ артикулов из кэша Фазы 1
- Рассчитывает конкретные перемещения с учётом:
  - Каждый склад-получатель в `warehouse_status.yaml` с `available: true`
  - Дневной лимит перераспределения на каждый склад
  - Защита доноров: не опускать ДЛ склада-источника ниже 70%
- Рассчитывает допоставки для артикулов, у которых нет остатков в нужных ФО

### Команда

```bash
python localization/run_permutations.py ooo
```

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `cabinet` | Имя кабинета (позиционный) | обязательный |
| `--safety-days` | Мин. запас дней продаж на доноре после отгрузки | 14 |

### Google Sheets — что появится

**Лист «Перемещения»**

Таблица: артикул → откуда → куда → сколько единиц. Готово для передачи в операционную команду.

**Лист «Допоставки»**

Артикулы, которых нет в нужных ФО — нужно поставить новую партию.

**Лист «Сводка»**

Суммарный эффект: сколько артикулов перемещается, прогнозный новый ИЛ, ожидаемая экономия.

**Лист «Обновление»**

Время последнего расчёта и источник данных (для контроля актуальности).

---

## Что делать с результатами

1. **Откройте лист «Перемещения»** — это готовое задание для склада
2. **Проверьте лист «Допоставки»** — отправьте на производство/закупку заявку
3. **Проверьте «Сводка»** — оцените ожидаемую экономию прежде чем принимать решение
4. Через 2–3 недели запустите Фазу 1 заново — проверьте фактический прогресс

> Toolkit строит рекомендации, решение принимает человек. Автоматического размещения заказов на перемещение нет.

---

## Частые вопросы

**Как часто запускать Фазу 1?**
Раз в 2–4 недели, или после крупных поставок.

**Можно ли запускать Фазу 3 без Фазы 2?**
Да. Фаза 3 читает кэш Фазы 1 напрямую. Roadmap нужен для стратегического планирования, Фаза 3 — для операций.

**Почему расчётный ДЛ расходится с показателем в WB Partners?**
WB считает по ISO-неделям, toolkit — по календарным дням. Расхождение до 3 п.п. — норма.

**Новосибирск недоступен — можно ли его включить?**
Откройте `warehouse_status.yaml` и установите `available: true`. Алгоритм сразу начнёт учитывать этот склад.
