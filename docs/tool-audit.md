# Аудит переплат — гайд

Как запустить аудит, прочитать результат и подготовить претензию.

---

## Зачем это нужно

WB выставляет счёт за логистику по своим расчётам. Иногда применяются неверные коэффициенты склада или не учитываются ваши тарифы по периодам. Аудит пересчитывает каждую строку по официальным тарифам WB из Supabase и показывает расхождение.

Результат используется для:
- Внутренней аналитики (сколько реально переплатили)
- Претензии в WB
- Судебного иска (лист «Рекомендации» содержит готовую формулировку)

---

## Перед первым запуском

Убедитесь, что ETL тарифов запущен и таблица `wb_tariffs` заполнена историческими данными за нужный период. Если данных нет — аудит будет использовать fallback из отчёта, что снижает точность.

```bash
# Проверить дату последней загрузки тарифов
python audit/etl/tariff_collector.py --check

# Загрузить тарифы за конкретную дату (если пропустили)
python audit/etl/tariff_collector.py --date 2026-01-15
```

Подробнее об ETL: [tariffs-db.md](tariffs-db.md).

---

## Запуск аудита

```bash
python audit/run_audit.py <кабинет> <дата_от> <дата_до>
```

**Примеры:**

```bash
# Аудит за Q1 2026
python audit/run_audit.py ooo 2026-01-01 2026-03-31

# Аудит за конкретный месяц с ручным КТР
python audit/run_audit.py ooo 2026-02-01 2026-02-28 --ktr 0.9

# Сохранить Excel в другую папку
python audit/run_audit.py ooo 2026-01-01 2026-03-31 --output-dir ~/Desktop
```

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `cabinet` | Имя кабинета из `cabinets.yaml` | обязательный |
| `date_from` | Начало периода `YYYY-MM-DD` | обязательный |
| `date_to` | Конец периода `YYYY-MM-DD` | обязательный |
| `--ktr` | Ручное переопределение КТР | 1.0 (из Supabase) |
| `--output-dir` | Папка для Excel | `.` (текущая) |

Скрипт выдаёт предупреждение, если тарифы в Supabase старше 2 дней.

## Что происходит внутри

```
WB API: reportDetailByPeriod v5 (отчёт за период)
WB API: content (объёмы товаров по артикулам)
Supabase: wb_tariffs (исторические коэффициенты складов)
    ↓
warehouse_coef_resolver — 3-уровневый приоритет коэффициентов:
  1. Fixation (если была активна на дату)
  2. Supabase wb_tariffs (исторические данные)
  3. dlv_prc из отчёта (fallback)
    ↓
logistics_overpayment — пересчёт каждой строки по официальной формуле
    ↓
Excel (12 листов)
```

## Листы Excel — как читать

### Свод

Итоговая таблица: суммарная начисленная логистика, пересчитанная по тарифам, расхождение в рублях и процентах. Разбивка по месяцам.

Если расхождение < 1% — данные совпадают, претензий нет. Если > 5% — есть основания для претензии.

### Переплаты

Все строки с расхождением > 0. По каждой строке:
- Номер поставки и дата
- Артикул, склад
- Что начислил WB vs. что должно быть по тарифам
- Разница (₽)

### Переплаты (формулы)

То же, что «Переплаты», но с видимыми формулами в ячейках — для проверки расчёта.

### ИЛ

Ваш Индекс Локализации по неделям в аудируемом периоде. Показывает, когда и как менялся ИЛ и как это влияло на тариф.

### Типы логистики

Разбивка по типам: короб, паллет, монопаллет. Для понимания структуры затрат.

### Размеры

Объёмные характеристики товаров из WB API. Используется при проверке расчёта логистики по литрам.

### Тарифы короб / Тарифы паллет

Исторические тарифы по каждому складу из Supabase. Позволяют проверить, какой тариф применялся на конкретную дату.

### Детализация

Построчный отчёт из WB API с добавленными пересчитанными значениями. Самый большой лист — для глубокого разбора.

### По артикулам

Сводка переплат по артикулам. Какие SKU принесли наибольшую переплату.

### По неделям

Динамика переплат по неделям. Помогает выявить периоды с аномально высокими расхождениями.

### Рекомендации

**Главный лист для претензии.** Содержит:

- Суммарная переплата за период (₽)
- Топ-10 артикулов по сумме переплаты
- Топ-5 складов с наибольшими расхождениями
- Динамика переплат по месяцам
- **Шаблон формулировки претензии** с подставленными цифрами

## Как подготовить претензию в WB

1. Запустите аудит за нужный период (минимум 1 месяц, оптимально — квартал)
2. Откройте лист «Рекомендации» — в нём уже готовый текст претензии
3. Проверьте цифры: суммарная переплата, топ артикулов, топ складов
4. Сохраните листы «Переплаты» и «Тарифы короб» как доказательства
5. Направьте претензию в личный кабинет WB Partners → Финансы → Обращения

**Что приложить к претензии:**
- Лист «Рекомендации» (основной документ)
- Лист «Переплаты» (построчное доказательство)
- Лист «Тарифы короб» (подтверждение применённых тарифов)

**Важно:** расхождение менее 3% может быть погрешностью из-за разных методологий округления. Подавайте претензию при расхождении > 5% или суммарной переплате > 10 000 ₽.

---

## Для судебного иска

Лист «Рекомендации» содержит формулировку, подходящую для искового заявления. При подаче в суд дополнительно потребуются:

- Договор с WB (оферта)
- Официальная тарифная таблица WB за аудируемый период (сохраняется в Supabase)
- Детализированный отчёт из WB (лист «Детализация»)

Рекомендуется привлечь юриста для оформления пакета документов.

## Частые вопросы

**Расхождение 2–3% — это нормально?**
Да. WB использует собственную методологию округления. Расхождение до 3% — в пределах допуска.

**Почему в Supabase нет тарифов за старый период?**
ETL собирает тарифы с момента запуска. Если аудит за период до запуска ETL — расчёт использует fallback из отчёта (`dlv_prc`). Точность снижается, но расчёт всё равно работает.

**Можно ли запускать аудит без Supabase?**
Да, но расчёт будет менее точным — все коэффициенты возьмутся из fallback (`dlv_prc` из отчёта WB). Для претензии рекомендуется использовать Supabase.

**Что делать, если `check_setup.py` говорит что тарифы старше 2 дней?**
Запустите `python audit/etl/tariff_collector.py` вручную, или настройте cron (см. [tariffs-db.md](tariffs-db.md)).
